# Accessibility (a11y) Manual Checklist — Quraan MVP

> T184 — WCAG 2.1 AA self-check. Run before every release. Each PR that touches
> UI components should re-run the relevant feature section. Automated coverage
> via `@axe-core/playwright` is in `tests/e2e/a11y.spec.ts`; this document
> covers human-judgment items the linter cannot enforce.

## Scope

- All routes in `frontend/src/app/app.routes.ts`
- Both languages: `en` (LTR) and `ar` (RTL)
- Both color schemes: light + dark (system preference)

## How to use this checklist

1. Pull the branch and run `npx ng serve` + the backend.
2. For each section, open the route in a clean browser (no extensions).
3. Tick `[x]` only after manually verifying. If unverifiable in this build,
   note **N/A** with a short reason and create a follow-up issue.

---

## 1. Keyboard navigation (WCAG 2.1.1, 2.1.2, 2.4.7)

- [ ] Tab order on every page follows visual reading order (LTR for `en`, RTL for `ar`).
- [ ] Every interactive element (links, buttons, form inputs, audio controls,
      tafsir toggle, bookmark toggle, search input) is reachable via Tab.
- [ ] Visible focus ring is present on every focusable element. Color contrast
      of the focus ring ≥ 3:1 against the adjacent background.
- [ ] No keyboard trap (Esc closes modals/panels; Shift+Tab navigates back).
- [ ] Skip link "Skip to main content" appears as the first Tab stop.

## 2. Screen-reader semantics (WCAG 1.3.1, 4.1.2)

Test with NVDA (Windows) or VoiceOver (macOS).

- [ ] Page `<title>` updates per route and is meaningful.
- [ ] One `<h1>` per page; heading hierarchy is contiguous (no h1 → h3 jumps).
- [ ] Surah list / search results / bookmarks list use `<ul>`/`<ol>` semantics.
- [ ] Ayah components expose Surah + Ayah number via `aria-label` or visible text.
- [ ] Audio controls expose play/pause state via `aria-pressed` or button label change.
- [ ] Form errors are announced (`aria-live="polite"` region or `role="alert"`).
- [ ] Tafsir panel is announced as a `dialog` / disclosure when opened.

## 3. Color & contrast (WCAG 1.4.3, 1.4.11)

- [ ] All text ≥ 4.5:1 contrast (≥ 3:1 for large/bold ≥ 18px).
- [ ] UI component boundaries (buttons, inputs, focus rings) ≥ 3:1.
- [ ] No information conveyed by color alone (e.g. error states also use icon/text).

## 4. Internationalization & RTL (WCAG 1.3.2, 3.1.2)

- [ ] `<html lang>` + `dir` switch correctly when toggling Arabic.
- [ ] Mirrored UI in Arabic: chevrons, icons, audio progress bar all flip.
- [ ] Arabic text uses an Arabic-shaped font; ligatures render correctly.
- [ ] Translations exist for all visible strings (no raw i18n keys leak through).

## 5. Forms (WCAG 1.3.1, 3.3.1, 3.3.2)

- [ ] Every input has a programmatic label (`<label for>` or `aria-label`).
- [ ] Required fields are indicated visually AND via `aria-required`.
- [ ] Error messages reference the input via `aria-describedby`.
- [ ] Sign-in error is generic (does not reveal email vs. password mismatch — also a security requirement, FR-029).

## 6. Reduced motion (WCAG 2.3.3)

- [ ] With `prefers-reduced-motion: reduce` enabled, smooth-scroll is skipped
      and decorative transitions are disabled. (Audio-position highlight stays
      — that's information, not decoration.)

## 7. Audio player (WCAG 1.4.2, R-09)

- [ ] Pause / resume keyboard-operable.
- [ ] Currently-playing Ayah is highlighted but **not auto-scrolled** (R-09).
- [ ] Audio errors are announced via `role="alert"` (FR-014).

## 8. Touch & pointer (WCAG 2.5.5)

- [ ] All interactive targets ≥ 44×44 CSS px on the mobile breakpoint.
- [ ] No hover-only affordances; bookmark/tafsir/audio all expose visible buttons on touch.

---

## Automated coverage (reference)

The `@axe-core/playwright` suite at `tests/e2e/a11y.spec.ts` runs on every PR
and catches the WCAG rules that can be detected programmatically:
contrast, missing labels, ARIA validity, landmark structure, color-only state.

Items in this manual list are explicitly the ones automation **cannot**
reliably check (heading order intent, RTL mirroring correctness, screen-reader
announcement quality, perceived focus ring contrast).
